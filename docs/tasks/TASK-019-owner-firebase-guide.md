> Орієнтовний час: 30–40 хвилин. Підготовка: комп'ютер, браузер з вашим Google-акаунтом (тим, де є Firebase), телефон Samsung під рукою.

## Крок 1. Створіть проєкт Firebase
1. Відкрийте https://console.firebase.google.com і увійдіть у свій Google-акаунт.
2. Натисніть **Create a project** («Створити проєкт»).
3. Назва: `Flowers` (можна `flowers-app`). Далі.
4. Google Analytics: **вимкніть** (перемикач вліво). Він нам не потрібен. Натисніть **Create project**, дочекайтесь «Your new project is ready» → **Continue**.
5. Тариф залишайте **Spark (безкоштовний)**. Картку не додавайте, доки не попросять (див. крок 7).

## Крок 2. Додайте Android-застосунок
1. На головній сторінці проєкту натисніть іконку Android (зелений робот) або **Add app → Android**.
2. **Android package name:** вставте точно `com.flowers.app` (без пробілів).
3. **App nickname:** `Flowers` (необов'язково).
4. **Debug signing certificate SHA-1:** вставте `36:F4:97:81:DB:F7:6A:7E:F2:3C:2D:D0:60:A5:FB:8D:8D:5A:97:CA`.
5. Натисніть **Register app**.
6. Натисніть **Download google-services.json** і збережіть файл. Нічого більше в майстрі (Gradle-код) робити не треба, цим займуся я; натисніть **Next → Next → Continue to console**.

### Куди покласти файл `google-services.json`
- Скопіюйте його в папку `C:\Users\cocro\Downloads\flowers\app\` (поруч із файлом `build.gradle.kts`). Ім'я файлу має бути точно `google-services.json` (без «(1)» чи «(2)», які додає браузер при повторному завантаженні).
- Файл **не комітимо в git**: я додам його в `.gitignore`. Google називає його вміст «не секретним», але ми не публікуємо його за замовчуванням. Не надсилайте його у відкритих чатах і не завантажуйте на GitHub. Якщо загубите, його можна завантажити знову: Налаштування проєкту (шестерня) → Your apps → Flowers → `google-services.json`.
- Потім напишіть мені «файл на місці», і я продовжу з кодом.

## Крок 3. Додайте SHA-256 до застосунку
1. Шестерня біля «Project Overview» → **Project settings** → вкладка **General**.
2. Прокрутіть до **Your apps** → ваш застосунок `com.flowers.app`.
3. У блоці **SHA certificate fingerprints** натисніть **Add fingerprint**.
4. Вставте SHA-256: `41:70:D6:04:C7:74:1C:FD:EE:1E:2A:EA:50:10:26:36:04:79:8C:0D:9B:B7:5B:D4:43:00:ED:0C:D0:E1:9D:17` → **Save**. (SHA-1 з кроку 2 там уже має бути; якщо ні, додайте й його.)

## Крок 4. Увімкніть Firebase AI Logic
1. У лівому меню: **Build** (або **AI**) → **AI Logic**. Якщо пункту не видно, скористайтесь пошуком угорі консолі: «AI Logic».
2. Натисніть **Get started**.
3. Коли попросять вибрати «Gemini API provider» (постачальника), оберіть **Gemini Developer API**.
4. Продовжуйте майстер до кінця (Continue / Enable). Він сам увімкне потрібні служби й **автоматично увімкне захист App Check** для AI Logic.
5. Якщо консоль пише, що потрібен тариф Blaze (оплата за використання): **зупиніться**, виконайте спершу крок 7 (бюджетні сповіщення), а тоді вирішуйте. За документацією Firebase, Gemini Developer API доступний і на безкоштовному Spark, і на Blaze; безкоштовні ліміти в документації не вказано, тож це точно покаже консоль. Напишіть мені, що саме вона вимагає, я не вмикатиму платне без вашої згоди.

## Крок 5. Налаштуйте App Check (захист від чужих)
1. Ліве меню: **Security → App Check** (або пошук «App Check»).
2. Вкладка **APIs**. Знайдіть рядок **Firebase AI Logic**.
3. Якщо там «Unenforced» (не примусово): клацніть на рядок → **Set up**. Якщо «Enforced», пропустіть цей пункт.
4. **Baseline protection:** оберіть **Enforced** → **Continue**.
5. **Replay protection:** залиште **Disabled** (вимкнено) → **Continue** → **Continue** (увімкнемо пізніше).
6. Вкладка **Apps**: зареєструвати застосунок для **Play Integrity** можна лише коли він з'явиться в Google Play (закрите тестування). Тому зараз цей пункт пропускаємо. Для тестів на вашому телефоні ми використаємо режим **debug** (крок 8).

## Крок 6. Обмеження ключів і доступу
1. Ключ Gemini з AI Studio, яким ви користувалися в застосунку раніше, більше не потрібен. Відкрийте https://aistudio.google.com/apikey і **видаліть** його (або перегенеруйте), після того як нова версія застосунку запрацює. Це прибере зайвий витік.
2. Не видаляйте ключі з приписками «(auto created by Firebase)» і не копіюйте їх нікуди. Усередині застосунку Gemini-ключа більше не буде: Google використовує свій службовий акаунт.
3. У Google Cloud console (https://console.cloud.google.com, обрати проєкт Flowers) → **APIs & Services → Credentials**: у ключа «Browser/Android key (auto created by Firebase)» у розділі **API restrictions** НЕ повинно бути «Generative Language API» / «Gemini Developer API». Якщо є, зніміть цю позначку й збережіть. Якщо сумніваєтесь, надішліть мені скриншот.

## Крок 7. Бюджетні сповіщення і ліміти (щоб не було несподіваного рахунку)
> Важливо: бюджетне сповіщення лише **попереджає листом, але НЕ зупиняє витрати**, лист може прийти із запізненням у кілька годин. Тому ми додатково знижуємо ліміти (пункт 4) і захищаємо запити App Check.
1. Зайдіть на https://console.cloud.google.com/billing → оберіть платіжний акаунт. Якщо його ще немає (Spark без картки), цей крок можна відкласти до моменту, коли ви вирішите перейти на Blaze, але **перед** переходом його виконайте обов'язково.
2. Меню **Budgets & alerts → Create budget**.
3. Тип **Alerts only**. Назва: `Flowers AI`. Охоплення: проєкт Flowers. Сума: наприклад **5 USD** на місяць (або менше).
4. Пороги залишити 50 %, 90 %, 100 %. Отримувачі: ваш e-mail. **Finish**.
5. Зниження ліміту запитів: у Google Cloud console відкрийте **APIs & Services → Enabled APIs → Firebase AI Logic API → Manage → Quotas & System Limits**, знайдіть «Generate content requests» (потрібний регіон) → **Edit quota** → поставте невелике значення (за замовчуванням 100 запитів на хвилину на користувача; для тестів достатньо 10–20) → **Submit request**.
6. Перевіряти витрати: Firebase → AI Logic → вкладка **Metrics**, а також Billing → Reports.

## Крок 8. Debug-токен App Check для вашого телефона (після того як я підготую збірку)
Цей крок ви зробите, коли я напишу «збірка з Firebase готова». Тоді:
1. Я встановлю тестову збірку на ваш Samsung (підключений кабелем).
2. Відкрийте застосунок і спробуйте згенерувати картку. Якщо з'явиться помилка про доступ, це очікувано: токен ще не додано.
3. Я знайду в журналі телефона рядок «Enter this debug secret into the allow list in the Firebase Console…» і надішлю вам токен (довгий набір літер і цифр).
4. Firebase → **Security → App Check → Apps** → ваш застосунок → меню з трьома крапками **⋮ → Manage debug tokens → Add debug token**. Вставте токен, дайте ім'я `S24 Ultra` → **Save**.
5. Знову згенеруйте картку «Філодендрон Біркін». Має запрацювати без ключа в Налаштуваннях.
6. Токен нікому не передавайте й не публікуйте (він дає доступ до ваших запитів).

## Release-ключ: звідки потім взяти SHA (для Google Play)
Зараз release-ключа немає: ми його створимо перед публікацією. Є два варіанти, залежно від того, чи вмикаєте ви Play App Signing (Google рекомендує, і новий застосунок його зазвичай має):
1. **Якщо застосунок у Google Play Console:** Play Console → ваш застосунок → **Test and release → Setup → App signing** (інколи «App integrity»). Там блок «App signing key certificate» показує **SHA-1 та SHA-256**. Саме **цей SHA-256** вставляємо в Firebase (Project settings → Your apps → Add fingerprint) і в App Check → Apps → Play Integrity. Також додайте SHA-256 «Upload key certificate» (на тій самій сторінці).
2. **Якщо підписуєте самі:** SHA виводиться командою `keytool -list -v -keystore <шлях до release.keystore> -alias <alias>`. Цю команду виконаю я, пароль від сховища знаєте тільки ви: мені потрібне лише значення SHA-256, не пароль.
3. Для Play Integrity у Play Console → **Release → App integrity → Play Integrity API → Link Cloud project** оберіть проєкт Flowers. Це може зробити лише **Owner** проєкту Firebase/Cloud.
4. **Файл release-сховища ключів і його пароль ніколи не надсилайте мені в чат і не комітьте.**
