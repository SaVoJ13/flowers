## 2. Опис дефекту та першопричина (Root Cause Analysis)
- **Симптом:** При введенні пошукового запиту у вкладці «Довідник» (наприклад, «монстера», «фікус», «спатифілум») список рослин не фільтрується або зникає/не знаходить рослини.
- **Першопричина:** 
  1. У SQLite оператор `LIKE` за замовчуванням є нечутливим до регістру (case-insensitive) **виключно для символів ASCII** (`A-Z`). Для кириличних символів (`а-я`, `і`, `ї`, `є`) стандартний SQLite `LIKE` є суворо регістрозалежним (`case-sensitive`). Запит «монстера» не збігався з назвою «Монстера деліціозна».
  2. Запит у `CatalogViewModel` виконував перепідключення flow через `flatMapLatest` до бази даних замість миттєвої реактивної фільтрації в пам'яті через Kotlin `contains(..., ignoreCase = true)` з повною підтримкою Unicode.
  3. У інтерфейсі `CatalogScreen` був відсутній кнопковий скидач пошуку (кнопка очищення `Clear`) та стан зворотного зв'язку (Empty State Placeholder), коли за запитом нічого не знайдено.
