- **Статус:** Draft / Готово до затвердження Власником (`Owner Approved`)

## 1. Бачення продукту та цілі

### 1.1. Продуктове бачення
Створити найзручніший, найпростіший та на 100% приватний офлайн-додаток для початківців, який усуває головні причини загибелі кімнатних рослин — перелив та брак практичних знань — за допомогою концепції «м'якої перевірки», навчальних подів-підказок та локальної діагностики симптомів.

### 1.2. Бізнес- та технічні обмеження
- **$0 витрат на сервери:** Повна відсутність бекенду та сторонніх платних API.
- **100% локальна робота:** Room (SQLite) + WorkManager / AlarmManager.
- **Жодної обов'язкової реєстрації:** Дані користувача зберігаються виключно на його пристрої.
- **Ненав'язлива монетизація:** Дослідження та чернетки реклами виключно на другорядних екранах (довідник, архів) без переривання процесу догляду.

## 2. Цільова аудиторія та персона

### 2.1. Цільовий користувач (Persona)
- **Хто це:** Людина, яка має вдома від 1 до 15 вазонів (подаровані рослини, озеленення квартири, нове хобі).
- **Рівень знань:** Початковий або середній. Не розрізняє складні ботанічні терміни, плутається в режимах поливу («поливати раз на тиждень» сприймає буквально).
- **Головні болі:**
  - Боїться засушити рослину, через що переливає її.
  - Отримує відчуття провини та розгубленості, коли жовтіє листя.
  - Дратується від популярних додатків через агресивні підписки ($40/рік) та незручні жорсткі графіки.

## 3. Основний користувацький цикл (Core Loop)

```
[1. Додавання рослини] ──> [2. Ознайомлення з подами виду]
         ▲                                   │
         │                                   ▼
[5. Аналіз змін у журналі] <── [4. Вибір усвідомленої дії] <── [3. М'яке сповіщення]
                                 (Виконано / Відкласти /          («Час перевірити ґрунт»)
                                  Пропустити / Є проблема)
```

1. **Додавання та знання:** Користувач додає вазон (наприклад, Заміокулькас або Монстера) -> отримує 3 короткі поди (як перевірити ґрунт, скільки світла треба, типова помилка).
2. **М'яке нагадування:** У призначений час надходить локальне сповіщення: *«Час перевірити [Назва]: огляньте ґрунт та стан»*.
3. **Усвідомлена дія:** Користувач перевіряє рослину й обирає дію в один клік:
   - **«Виконано»:** догляд проведено, запис внесено в журнал, таймер оновлено.
   - **«Відкласти»:** ґрунт ще вологий -> перенести перевірку на 1–3 дні.
   - **«Пропустити»:** рослині зараз нічого не потрібно, зберегти поточний цикл.
   - **«Є проблема / Перевірити стан»:** перехід до майстра симптомів.
4. **Аналіз та рефлексія:** Якщо щось не так, користувач вказує симптом (наприклад, жовтіють кінчики листя), додаток порівнює це з недавньою історією поливів із журналу, дає чіткий план дій і зберігає фото «було/стало».

## 4. Специфікація функціоналу MVP

### 4.1. Додавання та редагування рослини
- Власна назва рослини (обов'язково, наприклад: «Монстера на балконі»).
- Вибір виду з локального каталогу (пошук за назвою) або «Інший вид / Без виду».
- Кімната або локація (Спальня, Вітальня, Кухня, Балкон тощо) та рівень освітлення (Низький, Розсіяний, Пряме сонце).
- Необов'язкове фото рослини (з камери або галереї, зберігається локально у внутрішній пам'яті застосунку).
- Редагування всіх параметрів та безпечне видалення з підтвердженням.

### 4.2. Система навчальних карток («Поди-підказки»)
- **Що таке Под:** Коротка структурована картка знань (до 250 символів), яка пояснює одне конкретне практичне правило.
- **Типи подів для кожного виду:**
  1. *Вологість і перевірка:* як тактильно перевірити стан ґрунту саме для цієї рослини.
  2. *Освітлення:* де поставити в кімнаті (розсіяне світло, тінь, відстань від вікна).
  3. *Типова помилка новачка:* головний фактор ризику (наприклад, застій води в піддоні).
- **Загальні поди для початківців:** базові правила дренажу, обприскування, сезонності (зима/літо).
- Доступні на екрані деталізації рослини та як контекстні підказки під час догляду.

### 4.3. Головний екран «Сьогодні»
- Список карток завдань, згрупований за категоріями:
  - *Потрібно перевірити сьогодні;*
  - *Прострочені перевірки (з м'яким акцентом, без почуття провини);*
  - *Найближчі дні.*
- Швидкі дії на кожній картці: кнопка виконання (полив/догляд) або меню («Відкласти на 1/2/3 дні», «Пропустити», «Аналіз стану»).

### 4.4. Локальний планувальник нагадувань
- Налаштування інтервалів перевірки для кожного типу догляду (полив, підживлення, обприскування/протирання, поворот, пересадка).
- Працює через `WorkManager` з автономним плануванням локальних `Notification`.
- Стійкість до перезавантаження пристрою (`BOOT_COMPLETED`), зміни часу та часових поясів.
- Можливість увімкнути/вимкнути сповіщення як глобально, так і для окремої рослини.

### 4.5. Інтерактивний офлайн-аналіз стану (Діагностика симптомів)
- Покроковий майстер вибору ознак проблеми:
  - **Листя:** жовтіє цілком, сохнуть кінчики, чорніє по краях, в'яне/скручується, плямистість.
  - **Стебло/пагони:** м'які/гниючі біля основи, витягнуті й тонкі, опадання листя.
  - **Ґрунт:** не просихає > 10 днів, білий сольовий наліт, пліснява, неприємний запах.
  - **Шкідники:** павутинка (кліщ), білі липкі грудочки (борошнистий червець), літаючі мошки (сциариди).
- **Кореляція з журналом:** система перевіряє дату останнього поливу/підживлення:
  - *Приклад:* якщо листя опустилося, але полив був учора -> це ознака загнивання коренів від переливу, а не спраги!
- **Результат:** 1–2 найімовірніші причини, покроковий план безпечних дій (просушити ґрунт, змінити локацію, перевірити дренаж).
- Застереження: *«Цей аналіз є орієнтовною рекомендацією на основі типових симптомів догляду»*.
- Збереження картки огляду та фото в журнал рослини.

### 4.6. Журнал догляду та фотодинаміка
- Хронологічна стрічка подій по кожній рослині:
  - Полив, підживлення, пересадка, обрізка, протирання листя, діагностика стану.
- Можливість додавати текстові нотатки та фотографії.
- Візуальний режим «Було / Стало» для порівняння відновлення рослини після усунення проблеми.

### 4.7. Локальний каталог-довідник
- Каталог із 20–30 найпопулярніших невибагливих кімнатних рослин для початківців:
  - Сансевієрія, Заміокулькас, Спатифілум, Монстера, Епіпремнум, Фікус Бенджаміна/Каучуконосний, Красула (Грошове дерево), Хлорофітум, Драцена, Пеперомія, Аглаонема, Калатея тощо.
- Швидкий пошук та перегляд базових вимог і подів знань.

### 4.8. Налаштування
- Вибір теми (Світла / Темна / Системна).
- Вибір мови (Українська / English).
- Налаштування зручного часу надсилання сповіщень (наприклад, 09:00 або 19:00).
- Керування локальними даними: резервна копія (експорт JSON) та очищення даних.

## 5. Межі MVP: Що НЕ входить у перший реліз (Non-Goals)
1. **Платні хмарні ШІ-API:** жодних платних викликів. *(Оновлено 2026-11-20, TASK-021-B: реліз 1.0 використовує безкоштовний рівень Gemini через Firebase AI Logic лише для текстової картки за назвою рослини, ADR-009/013/015; фото-ШІ та платні API відкладено.)*
2. **Серверний бекенд та синхронізація:** власного бекенду немає ($0 бюджет). *(Оновлено: використовуються керовані безкоштовні сервіси Firebase на тарифі Spark: AI Logic, App Check, Firestore для скарг, ADR-014.)*
3. **Хмарні акаунти, реєстрація, авторизація через Google/Email.**
4. **Автоматичне розпізнавання хвороб за фото через нейромережу** (діагностика виключно інтерактивна за деревом симптомів; on-device ML фотоаналіз може розглядатися лише в майбутніх версіях після валідації попиту).
5. **Соціальні функції:** коментарі, публічні профілі, обмін рослинами.
6. **Погодні API:** прогноз погоди не підключається у MVP заради повної автономності та відсутності лімітів.

## 6. Метрики успіху MVP (Product Health Metrics)
1. **Zero-Overwatering Ratio:** Відсоток взаємодій зі сповіщеннями, де користувач обирає «Відкласти» або «Перевірити ґрунт» замість сліпого «Полив». (Показник усвідомленого догляду).
2. **Time to First Plant:** Менше 60 секунд від першого запуску додатку до додавання першої рослини та перегляду її подів.
3. **Retention 7d / 30d:** Повернення користувача для фіксації перевірки стану вазонів.
4. **Crash-free sessions:** > 99.5% стабільності в офлайн-режимі.
