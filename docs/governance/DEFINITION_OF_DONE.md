# DEFINITION OF DONE (Критерії готовності)

> Цей документ визначає стандарти якості та критерії завершення для всіх завдань, етапів та релізів проєкту **Flowers**.
> Червона лінія №1: «Готово» без доказу `DEFINITION_OF_DONE` суворо заборонено.
> Червона лінія №9: Автор змін не ставить `QA Verified` на власну роботу.

---

## 1. Загальні критерії для будь-якого завдання (Task DoD)
Завдання вважається виконаним (`Done`) лише тоді, коли:
1. **Код та контент:**
   - Код або документація повністю відповідають вимогам у картці завдання (`docs/tasks/<ID>.md`).
   - Відсутні тимчасові заглушки, `TODO`, закоментовані шматки коду (якщо вони не є частиною погодженого дизайну).
   - Дотримано правил ліцензування: сторонній контент або бібліотеки перевірено та внесено до `docs/THIRD_PARTY.md`.
2. **Тестування та верифікація:**
   - Написано юніт-тести для нової бізнес-логіки.
   - Усі автоматичні тести проходять успішно (зелений статус).
   - Проведено незалежну верифікацію іншим агентом (QA-субагентом) з наданням фактичних доказів (вивід тестів, скриншоти, логи).
   - Отримано статус `QA Verified` від верифікатора.
3. **Пам'ять та протокол:**
   - Журнал у картці завдання (`docs/tasks/<ID>.md`) заповнено за стандартом (п. 5.3 Конституції).
   - Створено або оновлено пов'язані записи в `CURRENT_STATE.md`, `TASK_BOARD.md` та `LESSONS.md`.
   - Зміни закомічено з чітким описом (наприклад, `feat(care): add moisture check pod logic`).
4. **Приватність та безпека:**
   - Жодних секретів, ключів чи персональних даних у коді та історії комітів.
   - Відсутній несанкціонований доступ до мережі або збір даних.

---

## 2. Критерії для воріт етапів (Stage Gates DoD)
Перехід до наступного етапу можливий лише за виконання наступних умов:
1. **Звіт етапу:**
   - Підготовлено звіт за встановленим шаблоном (`docs/templates/OWNER_REPORT.md` або `docs/reports/STAGE_<N>_REPORT.md`).
   - У звіті наведено лише фактичні числа та результати, без прихованих проблем чи довільних оцінок.
2. **Закриття питань Власника:**
   - Усі блокуючі питання внесені до `docs/governance/OWNER_INBOX.md` з чіткими варіантами та рекомендаціями.
3. **Рішення Власника:**
   - Отримано статус `Owner Approved` у журналі рішень `docs/governance/DECISIONS.md`.

## 3. Специфічні критерії для компонентів MVP
- **Каталог рослин та поди:**
   - Кожна рослина містить наукову та народну назву, базові параметри освітлення, вологості, поливу, перевірки ґрунту та типові помилки.
   - Усі дані мають перевірене джерело з зазначенням посилання та ліцензії в `docs/content/SOURCES.md`.
- **Аналіз стану (Діагностика):**
   - Дерево симптомів та ймовірних причин є детермінованим і повністю функціонує в офлайн-режимі.
   - Інтерфейс містить чітке застереження про межі локальної оцінки.
- **Сповіщення та планувальник:**
   - Нагадування працюють через `WorkManager` або `AlarmManager` з урахуванням перезавантаження пристрою (`BOOT_COMPLETED`) та зміни часового поясу.
   - Забезпечено коректну обробку дій: «Виконано», «Відкласти», «Пропустити».
- **Сховище даних:**
   - Усі дані зберігаються локально в базі Room.
   - Міграції схеми описані та перевірені тестами.
