- **Статус:** Затверджено Власником (`Owner Approved`).

- **Наслідки:** Застосунок отримує надпотужну комерційну цінність, зберігаючи надійність offline-first для збережених рослин.

## [ADR-009] 2026-11-19 — Міграція ШІ-генерації на Firebase AI Logic (Gemini Developer API) + App Check
- **Статус:** Запропоновано Архітектором; виконання плану залежить від дій Власника в консолі Firebase (акаунт Firebase у Власника є). Закриває проблему з ADR-008.
- **Контекст:** Користувач вводить власний ключ Gemini, він зберігається в застосунку. Документація Firebase прямо забороняє класти Gemini-ключ у мобільний застосунок; AI Logic використовує керований Google сервісний акаунт, а доступ захищає App Check.
- **Рішення:**
  1. Замінити ручний HTTP-виклик на SDK `firebase-ai` (провайдер Gemini Developer API, `GenerativeBackend.googleAI()`), модель з `GEMINI_MODEL` (`gemini-3.5-flash-lite`).
  2. App Check: Play Integrity для release, debug-провайдер лише для debug-збірок; примусове впровадження (Enforced) для AI Logic; Replay protection (limited-use tokens) пізніше.
  3. Прибрати з Налаштувань поле API-ключа, видалити `geminiApiKey` з `UserPreferences` (з очищенням збереженого ключа).
  4. `google-services.json` не комітити (`.gitignore`): рішення Архітектора за суворішим варіантом, документація Firebase не вимагає і не забороняє.
  5. Тариф: починати зі Spark; перехід на Blaze лише за згодою Власника і після бюджетних сповіщень. Alerts-only бюджет витрат не обмежує, тож додатково знижується квота запитів на користувача.
  6. Назву моделі пізніше винести у Firebase Remote Config (рекомендація документації); поки лишається `GEMINI_MODEL`.
- **Не підтверджено документацією:** розмір безкоштовних лімітів; чи потрібен Blaze саме в консолі проєкту; поведінка Play Integrity для APK, встановленого через adb; сумісність `firebase-ai` 18.2.0 з AGP 8.7.3 / Kotlin 2.0.21.
- **Наслідки:** Зміни в збірці, приватності (дані йдуть у Google/Firebase, App Check) і витратах належать до п. 3.2 конституції: потрібне схвалення Власника перед реалізацією та публікацією. Відкат: тег `pre-task-019` + `git revert` + App Check «Unenforced». План: `docs/tasks/TASK-019-firebase-ai-logic.md`; інструкція Власнику: `docs/tasks/TASK-019-owner-firebase-guide.md`.

## [ADR-010] 2026-11-19 — Зміна applicationId на `com.savoj.flowers`
- **Статус:** Рішення Власника (`Owner Approved`).
- **Контекст:** `com.flowers.app` уже зайнятий у Google Play (застосунок «Flowers App» від Flowers-Software GmbH). ID у Google Play унікальний і незмінний після публікації та фіксується при реєстрації в Firebase, тому змінити його треба ДО реєстрації в Firebase (TASK-019).
- **Рішення:**
  1. `applicationId = "com.savoj.flowers"` у `app/build.gradle.kts`.
  2. `namespace` і Kotlin-пакети (`com.flowers.app.*`) **не перейменовуємо**: namespace не впливає на ідентичність застосунку в системі та Google Play, а перейменування всіх пакетів дало б лише ризик без користі. Маніфест використовує відносні імена (`.MainActivity` тощо); провайдерів, FileProvider і deep link немає.
  3. Оновлено `docs/store/STORE_LISTING.md` і `CLOSED_TESTING_GUIDE.md`; історичні звіти й журнали попередніх завдань не змінюються (append-only).
- **Наслідки:** Для системи це новий застосунок: на телефоні Власника старий `com.flowers.app` видалено, дані (рослини, налаштування, API-ключ) не перенесено. Усі реєстрації (Firebase, App Check, Play Console, обмеження ключа) робляться з новим ID.

## [ADR-011] 2026-11-19 — Мультисорсова ізоляція Firebase App Check Debug Provider
- **Статус:** Прийнято (рішення Розробника за делегуванням, п. 3.1).
- **Контекст:** Під час реалізації TASK-019 необхідно підключити `DebugAppCheckProviderFactory` для тестування debug-збірок на реальному телефоні та емуляторі через adb, але суворо заборонено допускати витік debug-провайдера або токенів у релізний APK.
- **Рішення:**
  1. Залежність `firebase-appcheck-debug` підключено виключно через `debugImplementation`.
  2. Створено два незалежних source sets: `app/src/debug/java/.../AppCheckHelper.kt` (встановлює `DebugAppCheckProviderFactory`) та `app/src/release/java/.../AppCheckHelper.kt` (встановлює `PlayIntegrityAppCheckProviderFactory`).
  3. Виконано верифікацію dex релізного APK на відсутність `DebugAppCheckProviderFactory`.
- **Наслідки:** Чиста архітектура безпеки, релізні збірки компілюються виключно з Play Integrity без тестових артефактів.

## [ADR-012] 2026-11-19 — Модель монетизації: freemium + підписка Google Play Billing; ШІ-запити лише через серверний шлюз
- **Статус:** **ВІДКЛАДЕНО до підтвердження попиту** (рішення Власника 2026-11-19, див. ADR-013; початковий статус був «Пропоновано»). Нічого не реалізується до рішення Власника (п. 3.2 Конституції: монетизація, ціни, витрати, дані користувачів). Змінює частину ADR-007 (ШІ-картка перестає бути лише преміумом).
- **Контекст:** Мета Власника: застосунок, за який готові платити. Дослідження: `docs/product/AI_ROADMAP.md`. Firebase AI Logic дає лише ліміт запитів на хвилину на користувача (за замовчуванням 100 RPM), місячного ліміту на користувача немає; лічильник на телефоні обходиться очищенням даних. Безкоштовний (unpaid) рівень Gemini API за умовами Google використовує дані для покращення продуктів і дозволяє їх читання людьми.
- **Пропозиція:**
  1. Модель freemium: ядро (рослини, нагадування, каталог, офлайн-діагностика) безкоштовне. Безкоштовний ШІ-пул 6 запитів/міс. Premium (підписка Google Play Billing, місячна і річна) ≈100 запитів/міс (fair use) і всі ШІ-функції. Флагман: «Лікар рослин».
  2. Усі ШІ-виклики йдуть через Cloud Function-шлюз (App Check + анонімний Firebase Auth + лічильники Firestore). Статус підписки перевіряється на сервері (`purchases.subscriptionsv2:get`, RTDN).
  3. Тариф Blaze (потрібен для Cloud Functions і рекомендований для платних умов Gemini) після бюджетних сповіщень (крок 7 інструкції TASK-019) і глобального аварійного вимикача.
  4. Вимоги Play: дисклеймер «порада ШІ, не гарантія», кнопка скарги в застосунку, токсичність лише з перевірених джерел, цільова аудиторія 18+ (умови Gemini API).
  5. Порядок: R0 фундамент (TASK-020, 021, 022, 025) → R1 підписка і Лікар (TASK-023, 024) → R2…R5 (див. AI_ROADMAP §7).
- **Альтернативи:** (А) лише клієнтські ліміти без сервера: не захищає від обходу, лише для внутрішнього тестування; (Б) обов'язковий Google-вхід: надійніший облік, але тертя в онбордингу; (В) реклама замість підписки: суперечить принципам MONETIZATION_STRATEGY.md для потоків догляду.
- **Наслідки при затвердженні:** нові платні сервіси й витрати (Blaze), нові категорії даних (фото, анонімний ID, покупки), оновлення PRIVACY_POLICY/DATA_SAFETY/PERMISSIONS, зміна PRD. **Не підтверджено документацією:** спосіб виклику Gemini з сервера (spike у TASK-022), безкоштовні ліміти Gemini, Billing Library версія, процедура сервісного акаунта Play.

## [ADR-013] 2026-11-19 — Реліз 1.0 безкоштовний, на тарифі Spark, без підписки й фото-функцій
- **Статус:** Рішення Власника (`Owner Approved`). Відкладає ADR-012 до підтвердження попиту.
- **Контекст:** Власник не хоче вкладатися в застосунок, поки не підтверджено попит. Умови Gemini API (перевірені Власником за ai.google.dev/gemini-api/terms): користувачі 18+, застосунок не може бути орієнтований на осіб до 18 або ймовірно ними використовуватись. На безкоштовному рівні (без активного платіжного акаунта) Google може використовувати запити й відповіді для покращення продуктів, їх можуть читати люди-рецензенти; платний рівень вмикається лише через Cloud-проєкт з активним платіжним акаунтом. Ціна `gemini-3.5-flash-lite`: $0,30 / $2,50 за 1 млн токенів (вхід / вихід), підтверджено.
- **Рішення:**
  1. Публікуємо v1.0 безкоштовно: без підписки, без Blaze, без Cloud Functions, без фото-функцій, без платіжного акаунта. ШІ лише за назвою рослини через Firebase AI Logic на безкоштовному рівні.
  2. Для v1.0 прийнятно, що Google використовує запити безкоштовного рівня: у ШІ йде лише назва рослини, без персональних даних. Це розкривається в політиці конфіденційності й Data safety; у вікні генерації користувача просять не вводити особисті дані.
  3. Цільова аудиторія в Play Console: 18+.
