## 1. Середовище розробки та інструменти (Windows / Android)
- **[L-001] Шлях до JDK та Android SDK:**
  - *Контекст:* У терміналі PowerShell команда `java` глобально не розпізнається через відсутність у системному `PATH`, але повноцінний JDK (JBR) присутній у складі Android Studio: `C:\Program Files\Android\Android Studio\jbr\bin\java.exe`.
  - *Правило:* Для запуску Gradle CLI або компіляції з терміналу слід використовувати шлях до JBR або передавати `JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"`. Android SDK розташовано у `C:\Users\cocro\AppData\Local\Android\Sdk`.

- **[L-004] Використання JDK 21 для Gradle та Android:**
  - *Контекст:* JBR Android Studio містить експериментальну Java 25, несумісну з багатьма версіями AGP. На системі наявний стабільний офіційний JDK 21 (LTS) у `C:\Users\cocro\.jdks\jbr-21.0.11`.
  - *Правило:* Для збірки та тестів проєкту завжди задавати `JAVA_HOME="C:\Users\cocro\.jdks\jbr-21.0.11"`. З цим JDK Gradle 8.12.1 та AGP 8.7.3 працюють бездоганно.

- **[L-005] Регістрозалежність SQLite LIKE для кирилиці (Unicode):**
  - *Контекст:* У SQLite за замовчуванням оператор `LIKE` є нечутливим до регістру лише для символів ASCII (`A-Z`). Для кирилиці (українські літери) SQLite `LIKE` суворо регістрозалежний, через що запити у нижньому регістрі («монстера», «фікус») не знаходили назв у заголовковому регістрі («Монстера деліціозна»).
  - *Правило:* Для компактних наборів даних (наприклад, локальний каталог з 20–100 елементів) використовувати реактивну клієнтську фільтрацію у пам'яті через `contains(query, ignoreCase = true)` у Kotlin. Це гарантує повну підтримку Unicode (зокрема `і`, `ї`, `є`), миттєвий відгук без звернень до диску і захищає від специфіки SQLite.

- **[L-002] Кодування та символи в PowerShell:**
  - *Контекст:* У консолі Windows PowerShell за замовчуванням кодування може спричиняти спотворення кириличних символів при неправильному виклику команд.
  - *Правило:* Використовувати UTF-8 або перевіряти вивід через перенаправлення/нативні інструменти читання.
