# Правила роботи над Flowers

Проєкт працює за [CONSTITUTION.uk.md](CONSTITUTION.uk.md). Рішення Власника й конституція мають перевагу над цим файлом. Спілкуйтеся з Власником українською, просто і давайте лише один його наступний крок за повідомлення.

## Перед кожною сесією

Прочитайте повністю `CONSTITUTION.uk.md`, `CLAUDE.md` (якщо файл є), `docs/governance/CURRENT_STATE.md`, `DECISIONS.md` (особливо ADR-013–020), `TASK_BOARD.md`, `OWNER_INBOX.md`, останні п'ять сесій `SESSION_LOG.md`, `docs/release/RELEASE_1_0_PLAN.md`, `RELEASE_1_1_PLAN.md`, `docs/content/catalog/FORMAT.md`, `PLANT_LIST.md`, `docs/product/AI_ROADMAP.md` і `docs/governance/OWNER_REPORT_2026-11-20.md`. Звірте стан через `git status`, `git fetch`, відкриті PR та останні коміти `main`; коли зв'язку немає, прямо позначте, що віддалений стан не перевірено.

## Робочий порядок

- Кожне завдання: окрема гілка → PR → незалежна QA іншою моделлю, ніж автор → злиття лише після `QA Verified` і зеленого CI. Автор не верифікує власну роботу.
- Документальні PR, дані каталогу, ще не підключені до застосунку, і тести можна зливати після QA. Зміни, видимі в застосунку, спочатку встановлюйте на телефон і зливайте лише після перевірки Власником.
- `TASK_BOARD.md`, `CURRENT_STATE.md`, `SESSION_LOG.md`, `DECISIONS.md`, `OWNER_INBOX.md` лише доповнюйте. Після сесії оновіть перші три й дайте короткий звіт українською.
- Рішення Власника залишайте йому: питання з рекомендацією заносьте в `OWNER_INBOX.md`, а роботу продовжуйте над іншим завданням.
- Без явного дозволу Власника не змінюйте Firebase, Google Cloud чи Play Console, не створюйте витрат, тарифів, ключів підпису або паролів, не публікуйте застосунок, не видаляйте дані й не переписуйте історію Git.
- Для збірки потрібен JDK 21. На телефон встановлюйте лише поверх: `adb install -r`; не видаляйте застосунок і не очищуйте дані. Не додавайте `app/google-services.json` до Git і не показуйте його вміст.
- Факти про API, бібліотеки й вимоги Google Play перевіряйте за актуальною офіційною документацією. Безпеку тварин і дітей у каталозі підтверджуйте джерелами; schema 2 застосовуйте після фіксації затвердження ADR-020 у журналі рішень. Сумнів позначайте `UNKNOWN`. ASPCA може бути лише посиланням. Власні тексти мають проходити `OverlapChecker` (< 8 послідовних слів).
