## [ADR-001] 2026-11-18 — Підключення Governance та Конституції команди агентів v2.0
- **Статус:** Прийнято (рішення Керівника за делегуванням, п. 3.1).
- **Контекст:** Старт розробки Android-застосунку для догляду за кімнатними рослинами. Потрібно зафіксувати правила співпраці, розподіл ролей, протокол пам'яті та червоні лінії.
- **Рішення:**
  1. Скопійовано `CONSTITUTION.uk.md` та `CONSTITUTION.en.md` без змін до `docs/governance/`.
  2. Створено чернетку `docs/governance/PROJECT_PROFILE.md` із заповненням відомих параметрів та виносом невідомих до `OWNER_INBOX.md`.
  3. Створено структуру файлів пам'яті (`CURRENT_STATE.md`, `TASK_BOARD.md`, `SESSION_LOG.md`, `LESSONS.md`, `OWNER_INBOX.md`, `DEFINITION_OF_DONE.md`).
  4. Створено структуру каталогів для завдань, дорожньої карти та звітів.
- **Наслідки:** Робота команди підпорядкована Конституції v2.0. Будь-які зміни верифікуються незалежно, а етапи проходять через схвалення Власника.

## [ADR-002] 2026-11-18 — Архітектурна орієнтація на 100% офлайн (нульові серверні витрати)
- **Статус:** Прийнято (рішення Керівника за делегуванням у межах продуктової гіпотези).
- **Контекст:** Продуктова гіпотеза вимагає розробки легкого додатку без серверних витрат ($0) та без обов'язкової реєстрації.
- **Рішення:** Затверджено базовий технологічний вектор: Android (Kotlin, Jetpack Compose), Room (SQLite) для локального збереження даних, WorkManager для локальних сповіщень. Відхилено будь-які платні бекенди або хмарні ШІ-API на етапі MVP.
- **Наслідки:** Застосунок автономний, швидкий, приватний, з нульовою вартістю інфраструктури для Власника.

## [ADR-006] 2026-11-18 — Прямий мандат Власника на автономне завершення розробки MVP та підготовку збірки для телефону
- **Статус:** Затверджено Власником (`Owner Approved`).
- **Контекст:** Власник надав пряму інструкцію: «я зараз уходжу даю тобі дозвіл приймати найкращі рішення, якщо додаток буде готовий то завантаж на телефон».
- **Рішення:**
  1. Затверджено результати Етапу 2 (UX та контент) за [INBOX-005].
  2. Надано делегування на проведення Етапів 3 (Архітектура та дозволи), 4 (Реалізація MVP), 5 (QA-перевірка), 6 (Матеріали Google Play) та збірку APK для встановлення на телефон.
  3. Якщо фізичний пристрій або емулятор з'явиться в `adb devices`, провести автоматичне встановлення `adb install`; якщо ні — надати готовий перевірений APK та команду встановлення в 1 клік.
- **Наслідки:** Команда агентів автономно реалізує проєкт під ключ із дотриманням Конституції v2.0, заборони самоверифікації (QA верифікує окремий субагент) та зелених автотестів.

## [ADR-007] 2026-11-18 — Затвердження бізнес-моделі Freemium та інтеграції ШІ-генератора догляду (Gemini API)
- **Статус:** Затверджено Власником (`Owner Approved`).
- **Контекст:** Власник погодив монетизаційну модель Freemium: безкоштовний базовий та хмарний каталог (Варіант 1) + ШІ-генерація картки догляду за назвою рослини (Варіант 3 через Gemini API) для преміум-підписників.
- **Рішення:**
  1. Розширити концепцію продукту:
     - **Free рівень:** Локальна база (20 видів) + оновлення каталогу з відкритих джерел/CDN, поди для новачків, нагадування, офлайн-діагностика симптомів.
     - **Premium рівень:** Можливість додавати будь-яку рідкісну або екзотичну рослину — ШІ (Gemini) автоматично формує персональну картку з точним графіком перевірки ґрунту, світлом, поливом і токсичністю та зберігає в локальну базу телефону.
  2. Додати дозвіл `android.permission.INTERNET` у `AndroidManifest.xml` для мережевих запитів.
  3. Реалізувати Крок 1 для тестування на смартфоні Власника: інтерфейс генерації, сервіс Gemini API, збереження в Room, екран Налаштувань із можливістю вказати / оновити API-ключ та перемикач преміум-режиму.
- **Наслідки:** Застосунок отримує надпотужну комерційну цінність, зберігаючи надійність offline-first для збережених рослин.
