# TASK-027 — Інструкція для Власника: база Firestore для скарг на ШІ

Простою мовою. Усе на безкоштовному тарифі Spark, картка не потрібна. Виконуйте **після** злиття PR TASK-027 (файл правил `firestore.rules` лежить у корені репозиторію). Орієнтовно 15 хвилин.

## Крок 1. Створити базу
1. Відкрийте https://console.firebase.google.com і оберіть проєкт застосунку Flowers.
2. Ліве меню: **Build → Firestore Database → Create database**.
3. **Edition (версія): Standard.**
4. **Database ID: `(default)`** (не змінюйте; безкоштовна квота діє на одну базу, і це має бути саме `(default)`).
5. **Location (регіон): `eur3 (Europe)`.** Чому: це мультирегіон у Європі (Бельгія + Нідерланди), дані користувачів лишаються в ЄС (простіше з політикою конфіденційності та GDPR), а мультирегіон надійніший за один центр. Затримка нам не важлива: скарги пишуться рідко. **Регіон потім змінити не можна.** Якщо консоль для `eur3` покаже вимогу тарифу Blaze або платіжну картку, оберіть `europe-west1` (Бельгія). *Не підтверджено документацією, чи безкоштовна квота діє саме для eur3; перевіряємо підказкою в консолі.* Якщо жоден європейський варіант без Blaze не доступний, зупиніться і напишіть мені.
6. Режим: **Start in production mode** (усе закрито; потім ми вставимо правила).
7. Натисніть **Create** і зачекайте ~1 хвилину.

## Крок 2. Опублікувати правила
1. У Firestore відкрийте вкладку **Rules**.
2. Видаліть увесь текст, вставте повний вміст файлу `firestore.rules` з репозиторію.
3. Натисніть **Publish**. Консоль має показати «Rules published» без червоних помилок.
Що роблять правила: застосунок може **лише створити** скаргу строго заданого формату; читати, змінювати й видаляти скарги з телефону неможливо. Скарги читаєте тільки ви в консолі.

## Крок 3. Перевірити з телефону
1. Встановіть збірку з PR TASK-027 (я покладу її на телефон через adb, коли він розблокований).
2. Каталог → ШІ-пошук рослини (наприклад «tulip») → на картці **«Поскаржитися на відповідь ШІ»** → оберіть причину → **Надіслати**. Має з'явитися «Дякуємо! Скаргу надіслано.»
3. У консолі: **Firestore Database → Data → reports** → має бути новий документ з полями: feature, plantQuery, responseText, reason, comment, appVersion, createdAt, expireAt. Поле `comment` є лише якщо ви його вписали. Скажіть мені «скарга є» (або що не з'явилась).

## Крок 4. Зберігання 12 місяців (автоматичне видалення)
1. Firestore → вкладка **TTL** (Time-to-live) → **Create policy**.
2. Collection group: `reports`; Timestamp field: `expireAt` → Create.
Тоді кожна скарга видалиться приблизно через 12 місяців (видалення робиться протягом доби після дати, не миттєво). *Чи доступний TTL на Spark, у документації прямо не підтверджено; якщо консоль скаже, що ні, напишіть: тоді вручну чистимо раз на рік.*

## Крок 5. App Check для Firestore (захист від чужих запитів)
1. **Build → App Check → вкладка APIs → Cloud Firestore.**
2. Спершу залиште **Monitor** (спостереження) і перегляньте метрики після кількох скарг.
3. **Enforce (увімкнути примусово) тільки після того, як застосунок з Google Play пройшов Play Integrity (TASK-021-A, крок 10 плану 1.0).** Якщо увімкнути раніше, скарги з установлених вручну релізних збірок перестануть проходити (debug-збірка з уже зареєстрованим токеном працює).
4. Після ввімкнення Enforce відправте ще одну тестову скаргу і повідомте мені результат.

## Якщо щось пішло не так
Скріншот помилки мені. Нічого не видаляйте. Базу можна видалити й створити заново (регіон змінюється лише так), скарг там поки немає.
