# TASK-022: ШІ-шлюз, квоти, безпека відповіді

## 1. Загальні відомості
- **ID:** TASK-022 · **Тип:** Платна версія / бекенд · **Дата створення:** 2026-11-19
- **Статус:** **ВІДКЛАДЕНО** до підтвердження попиту (ADR-013, 2026-11-19). Колишній статус: ПРОПОНОВАНО. Не починати без рішення Власника за ADR-012, згоди на Blaze і виконаного кроку 7 (бюджет) інструкції `TASK-019-owner-firebase-guide.md`.
- **Пов'язане:** `docs/product/AI_ROADMAP.md` (§4, §6, §8), ADR-009, ADR-011, ADR-012 (пропоновано)
- **Мета:** виклики Gemini проходять через наш Cloud Function-шлюз, що перевіряє App Check і користувача (анонімний вхід), рахує місячний пул запитів і не дає обійти ліміт на телефоні. Додати дисклеймер і кнопку скарги на ШІ-відповідь (вимога Google Play).

## 2. Обсяг
1. Власник: Blaze + бюджет (крок 7), `firebase init` не потрібен від Власника, лише доступ до консолі за потреби.
2. Spike (перший крок): як шлюз викликає Gemini (Gen AI SDK/Genkit з ключем у Secret Manager або Vertex AI). Записати висновок і вартість у DECISIONS. Якщо жоден варіант не підходить: зупинитись і запитати Власника (OWNER_INBOX).
3. Firebase Auth (анонімний вхід) у застосунку; Cloud Function (callable, `enforceAppCheck: true`); Firestore: `usage/{uid}/{YYYY-MM}`, `reports/{id}`, глобальний лічильник/вимикач.
4. Пул безкоштовних запитів 6/міс (значення з Remote Config або константи на сервері).
5. Метрики токенів (`usageMetadata`) у кожному записі використання.
6. UI: дисклеймер, кнопка «Поскаржитися на відповідь ШІ» (діалог причини), повідомлення «ліміт вичерпано».
7. Перемикання `generatePlantWithAi` з прямого `Firebase.ai(...)` на шлюз.
8. Правила безпеки Firestore: клієнт не пише в `usage`, `entitlements`.

Поза обсягом: Play Billing (TASK-023), Лікар рослин (TASK-024), оновлення політики приватності (TASK-021).

## 3. Критерії приймання
1. Blaze підключено Власником після кроку 7; сума бюджету записана в журналі.
2. Spike виконано, рішення записано в DECISIONS; ключ Gemini відсутній у застосунку та git (`git grep -i "AIza"` порожній).
3. Запит без чинного App Check токена або без автентифікації відхиляється функцією (перевірено).
4. Безкоштовний uid: перші 6 запитів у місяць успішні, 7-й повертає «квоту вичерпано» без звернення до Gemini; автотест на емуляторі Firebase і перевірка на телефоні.
5. Очищення даних застосунку не скидає пул для того самого uid; поведінку нового uid (перевстановлення) перевірено й записано в журнал як відомий ризик.
6. Глобальний добовий вимикач працює (тест із заниженим порогом).
7. Кожен запит зберігає кількість вхідних/вихідних токенів; у журналі картки наведені фактичні середні значення (замінюють оцінки AI_ROADMAP §2).
8. Дисклеймер видно під кожною ШІ-відповіддю; кнопка скарги створює документ у `reports` і не виводить із застосунку (перевірено на телефоні).
9. Усі наявні 18 юніт-тестів зелені, додано нові (квота, мапінг помилок); `assembleDebug` та `assembleRelease` успішні.
10. Незалежна QA іншою моделлю/агентом; live-перевірка Власником на пристрої.

## 4. Ризики
- Затримка шлюзу (холодний старт функції) → показувати індикатор, мінімум-інстансів не вмикати без згоди Власника (гроші).
- Нові анонімні uid обходять безкоштовний пул → глобальний вимикач, моніторинг, відомий ризик.
- Витрати Blaze: перші тижні щодня переглядати метрики.
- Відкат: знімок `pre-task-022`, повернення клієнта на пряме `Firebase.ai(...)` (PR revert); у консолі функцію можна вимкнути.
