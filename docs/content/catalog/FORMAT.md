# Формат каталогу рослин, `schema: 2` (TASK-038; безпека за ADR-020, ПРОПОЗИЦІЯ: чекає затвердження Власника)

> Джерело істини: `app/src/main/assets/catalog/` (копія файлів у `docs/content/catalog/`, тест `docs copy of catalog equals assets` ловить розбіжність). Валідатор: `app/src/test/java/com/flowers/app/catalog/CatalogValidator.kt`, тести: `CatalogValidatorTest` (запускаються в `testDebugUnitTest`). Рішення Власника: ADR-015, ADR-018 (формат, Room v3 і правило «ID рослин не видаляються» затверджено 2026-11-20).

## 1. Файли
```
catalog/
  manifest.json        { "contentVersion": N, "schema": 2, "batches": ["b00", "b01", ...] }
  sources.json         { "<sourceId>": { "title", "publisher", "url", "kind" } }
  b00.json … b07.json  масив карток (≈25), одна партія = один файл
```
- `manifest.contentVersion`: ціле ≥ 0. `0` означає «партій ще немає». З першою злитою партією B0 стає ≥ 1. Кожна зміна карток чи нова партія збільшує число.
- Файл партії `bNN.json` обов'язково перелічений у `manifest.batches` (і навпаки).
- Імпорт (TASK-037) порівнює `contentVersion`, а не «порожність таблиці», і чіпає лише записи `origin=BUILTIN`.

## 2. `sources.json`
Кожен запис: `title`, `publisher`, `url` (лише `https://`), `kind` ∈ `extension | botanical | society | other`. `sourceId`: `[a-z0-9_]+`.
**ASPCA не може бути джерелом** (дані не копіюються, ADR-014): `url` з `aspca.org` валідатор відхиляє. ASPCA лише як посилання `safety.aspcaUrl`.

## 3. Картка
| Поле | Тип | Правило |
|---|---|---|
| `id` | рядок | `[a-z0-9_]+`, 2–60, унікальний, **стабільний назавжди**. 20 наявних ID з Room v2 лишаються (список у валідаторі й `PLANT_CATALOG.json`); нові: латинський slug (`monstera_deliciosa`) |
| `latin`, `family` | рядок | 3–80, 3–60 |
| `retired`, `replacedBy` | bool, id/null | `retired=true` потребує `replacedBy`, що існує в каталозі; картка не видаляється ніколи |
| `care.difficulty` | enum | `VERY_EASY, EASY, MEDIUM, DEMANDING` |
| `care.lightMin/lightMax` | enum | `LOW, MEDIUM, HIGH, DIRECT`; `lightMin ≤ lightMax` (пороги lx: план 1.1 §6.2) |
| `care.checkIntervalDays` | ціле | 3–28 |
| `care.humidity` | enum | `LOW, MEDIUM, HIGH` |

| `safety.cats`, `safety.dogs`, `safety.children` | enum | `NON_TOXIC, LOW, MODERATE, SEVERE, TOXIC, UNKNOWN` (розділ «Безпека, schema 2» нижче) |

| `safety.toxicParts` | масив enum | `LEAVES, STEMS, SAP, ROOTS, BULBS, FLOWERS, FRUIT, BERRIES, SEEDS, ALL_PARTS, UNSPECIFIED`; непорожній, якщо є токсичний рівень; порожній, якщо жодного |

| `safety.explanation.{uk,en,ru,pl}` | рядки 15–250 | коротке фактичне пояснення мовою; при `sourcesDisagree=true` має прямо сказати, що джерела розходяться |
| `safety.sourceIds` | масив | обов'язкове непорожнє, якщо є рівень ≠ `UNKNOWN`; існуючі джерела |

| `i18n.<lang>.name` | рядок 2–60 | uk/ru: кирилиця; en/pl: латиниця |

| `notes` | рядок ≤ 300, необов'язково | розбіжності між джерелами тощо (не усереднювати мовчки) |

Зайві поля заборонені (захист від друкарських помилок). Заборонені в рядках (також у `aspcaUrl`, `notes`, `aliases`) символи за категоріями Unicode: керівні (Cc, зокрема переведення рядка), форматні/нульової ширини/двоспрямовані (Cf: U+200B, U+202E, U+061C, U+00AD тощо), приватні (Co), сурогати (Cs, зокрема неспарені), роздільники рядків і абзаців, U+FFFD, непризначені коди. У текстах і назвах en/pl заборонені кирилиця й грецькі літери (проти гомогліфів, що обходять перевірку оригінальності). `aspcaUrl` ≤ 300 символів без пробілів. `factChecked` між 2025 і 2100 роками. BOM на початку файлу заборонений. `notes` непорожнє або відсутнє; `aliases` без дублів (без урахування регістру); `safety.sourceIds` без дублів; `factChecked` існуюча дата; назва uk/ru переважно кирилична (кирилиця > половини літер); `replacedBy` без циклів.

**JSON строгий:** файли читаються у строгому режимі (без коментарів, одинарних лапок, ключів без лапок, кінцевих ком), **дубль ключа = помилка**; так само має читати імпортер (TASK-037). `contentVersion: 0` вимагає порожній `batches`, `contentVersion ≥ 1` потребує хоча б однієї партії. У `assets/catalog` дозволені лише `manifest.json`, `sources.json`, `bNN.json` (два розряди); будь-який інший файл = помилка тесту.

## 4. Правила партій
1. Зібрати факти: на кожну рослину ≥ 2 джерела догляду + джерело безпеки; URL у `sources.json`; розбіжності в `notes`.
2. Тексти кожною мовою пишуться **окремо за фактами**, не дослівним перекладом; власні формулювання.
3. **Оригінальність (автоматично, TASK-038-B):** для кожної партії `bNN.json` обов'язковий файл `docs/content/catalog/drafts/bNN.excerpts.json` вигляду `{"<id рослини>": ["уривок тексту джерела, ≥ 40 символів", ...]}` (≥ 1 уривок на картку; це фрагменти, з яких автор брав факти). Тест `OriginalityValidator` перевіряє всі текстові поля всіх мов: найдовша послідовність слів, спільна з будь-яким уривком, має бути **< 8 слів** (`OverlapChecker.MAX_SHARED_WORDS`). Немає файлу чи уривків для картки = помилка. Файли `drafts/` не потрапляють в assets застосунку.
4. Безпека для тварин/дітей лише з джерелом; сумнів = `UNKNOWN`. Помилка в бік «безпечно» гірша за `UNKNOWN`. Правила розділу «Безпека, schema 2».
5. Валідатор зелений. Незалежна QA іншою моделлю: вибірка ≥ 30 % (мінімум 8) карток звіряється з джерелами за URL, **100 % прапорців безпеки**, перевірка оригінальності, звіт із числами. Модель, що збирала/писала партію, не є QA тієї партії (ADR-017).
6. Вибірка Власника: 3–5 карток партії. Для pl/en без носія `nativeReviewed=false` (рішення Q-1.1-5: російську перевіряє Власник; польську перевіряє носій, якого знайде Власник, на вибірці з 5 карток і тексті магазину; англійська публікується з позначкою «без перегляду носієм»).
7. Після злиття партії `contentVersion++`, ID не змінюються.

## 5. Що перевіряє валідатор (зведення)
Наявність і тип усіх полів; безпека schema 2 (рівні, `toxicParts`, `sourcesDisagree` і його маркер у кожній мові, `explanation` 4 мовами з правильним скриптом, нейтральний текст для всіх `UNKNOWN`, джерела); унікальність `id`; enum-и; межі довжин; наявність усіх 4 мов; кирилиця/латиниця в назвах; існування кожного `sourceId`; `safety` ≠ `UNKNOWN` ⇒ є джерело; ≥ 2 джерела догляду; ASPCA не джерело, `aspcaUrl` лише з aspca.org; керівні символи; `retired/replacedBy`; файли партій ↔ manifest; **при `contentVersion ≥ 1` усі 20 наявних ID присутні**.

## Безпека, schema 2 (ADR-020, пропозиція)
Причина: бінарне `TOXIC/NON_TOXIC` перебільшувало або спрощувало (напр. *Pachira aquatica*: джерело каже низька тяжкість, лише для котів, отруйне лише насіння, а раніше було `TOXIC`).

- **Рівні** окремо для котів (`cats`), собак (`dogs`) і дітей (`children`): `NON_TOXIC` (лише за ЯВНИМ твердженням джерела для цієї групи й за відсутності суперечних тверджень), `LOW`, `MODERATE`, `SEVERE` (тяжкість, названа джерелом: NC State «low/medium/high severity», RHS «mildly toxic» тощо), `TOXIC` (джерело каже «токсична/шкідлива», тяжкість не вказано), `UNKNOWN` (явних даних для групи немає; відсутність згадки ≠ безпека; «токсична для людей» не дає даних про котів).
- **Отруйна частина** `toxicParts`: з джерела; якщо рослина токсична, але частина не вказана, `["UNSPECIFIED"]`; `ALL_PARTS` і `UNSPECIFIED` не поєднуються з іншими значеннями; для рослини без токсичних рівнів масив порожній.
- **Суперечності:** якщо джерела однієї картки по-різному оцінюють групу (одне `NON_TOXIC`, інше токсична; або різні ЯВНІ тяжкості; або суперечність усередині однієї сторінки), ставиться `sourcesDisagree: true` і обирається **обережніший** рівень (`SEVERE > MODERATE > TOXIC > LOW > NON_TOXIC`). Не вважається суперечністю: одне джерело каже «токсична» без тяжкості, інше «low severity» (це узгоджено з `LOW`). Докладний текст розбіжності: у `notes` (англійською) і `drafts/safety.evidence.json`.
- **Порядок «обережності» рівнів** (один для суперечностей і для показу «найвищого з трьох»): `SEVERE > MODERATE > TOXIC > LOW > NON_TOXIC`; `UNKNOWN` не входить у порядок (показується лише якщо всі три `UNKNOWN`).
- **Діти (`children`):** рівень = тяжкість сторінки джерела, якщо є тег «Problem for Children» або «Poisonous to Humans» у полі Problems чи явне речення про людей/дітей; джерело про людей без названої тяжкості дає `TOXIC`; інакше `UNKNOWN`. Заголовок розділу шаблону NC State «Poisonous to Humans:» сам по собі твердженням не вважається. Тяжкість `LOW/MODERATE/SEVERE` має бути названа джерелом (опис симптому без тяжкості дає `TOXIC`).
- **Перевіряє QA, а не валідатор:** що `NON_TOXIC` стоїть лише за явним твердженням джерела й без суперечних тверджень в інших джерелах картки; що джерело описує саме цей таксон (синонім з прямою вказівкою допустимий, інший вид чи рід ні; якщо рід, це записано в `notes`).
- **Пояснення** `explanation` обов'язкове для кожної картки (4 мови): хто в групі ризику, тяжкість, отруйна частина, а при розбіжності слова «джерела розходяться» (валідатор перевіряє наявність маркера в кожній мові). Для всіх `UNKNOWN` це нейтральне «безпека не підтверджена джерелами».
- **Показ у застосунку (для TASK-037):** найвищий із трьох рівнів + пояснення; `UNKNOWN` = нейтральний текст `SafetyNotice(toxic=false)`; токсичний рівень = попередження з поясненням і порадою звернутися до ветеринара/лікаря (ADR-018); `sourcesDisagree` = додатковий рядок «джерела розходяться».
- **ASPCA** лишається лише посиланням (ADR-014); її дані не копіюються й не є джерелом рівнів.
- **Свідчення** (цитати з джерел для кожного рівня) зберігаються поза assets: `docs/content/catalog/drafts/safety.evidence.json`.
